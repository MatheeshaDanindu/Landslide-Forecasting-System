| 11 | Threshold fixed at 0.5 | **FIXED** | `train.py::train_one_model` sweeps 0.05–0.95 on the inner validation split after training, freezes the F1-maximizing threshold before the outer test cluster is scored, and saves it to each checkpoint's `meta.json`. `evaluate.py` reads that value by default (falls back to 0.5 only if no meta file exists). |

Mean ± SD (n=8, each cluster one independent observation) and a t-interval for PR-AUC are reported in EXPERIMENTAL_RESULTS.md; a paired Wilcoxon signed-rank test across folds compares architectures (verified with `scipy.stats.wilcoxon`, not hand arithmetic). |

No independent `pos_weight` was added (alpha already serves this role; a second free parameter was judged not worth the added config surface for one fold's worth of data). |

This inconsistency is now called out explicitly in code comments in `train.py`/`evaluate.py` rather than silently worked around. |

## New issues found this pass

| # | Issue | Status | Evidence |
|---|---|---|---|
| 25 | Negative-sampling leakage across the test buffer | **CONFIRMED, FIXED** | `sample_negative_centers` sampled candidate locations uniformly over an entire Sentinel-2 tile's bounding box, excluding only a ring around *training* polygons. It never excluded the held-out test cluster or its 3,060 m buffer, so any tile spanning both regions could produce negative training patches inside the test region — independently confirmed by reading the code and reproduced via a direct trace of `extract_fold_patches`/`sample_negative_centers`. Fixed by passing the fold's `test_buffer` geometry in as an `extra_exclusion_geom` (commit `4a59be3`). All prior fold/model checkpoints predate the fix and are being retrained. |
| 26 | Sub-30 m polygons rasterized as background, not excluded | **CONFIRMED, NOT FIXED** | `rasterize_polygons` is only ever called on the primary (≥30 m) cohort; the 30.5% of polygons below the minimum mapping unit are never rasterized at all when they happen to fall inside a positive or negative patch window, so their pixels are silently labeled background (0) rather than excluded from the loss/metrics. This is a conservative-but-biased choice (it can only suppress recall, not inflate it), not fabrication, but is undocumented in the per-fold results and should be stated as a limitation. |
